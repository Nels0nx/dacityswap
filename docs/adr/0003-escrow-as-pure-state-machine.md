# ADR 0003: Escrow is a pure state machine

- Status: accepted
- Date: 2026-11-17

## Context

The rules for when money may move must be identical in the UI preview, on the server and
on-chain, and they must be easy to audit.

## Decision

Model a trade as a finite state machine in dependency-free TypeScript. `applyEvent(record,
event, now)` is a pure function: the clock is passed in, nothing is mutated and each call appends
to the record's history. The Solidity contract mirrors the same states.

## Consequences

- The rules can be tested exhaustively without a database, a network or mocked time.
- Every order carries its own audit trail.
- The server needs a thin layer that loads a record, applies an event and saves the result in
  one transaction. That layer, not the core, handles concurrency.
- Two implementations (TypeScript and Solidity) can drift. A shared set of test scenarios, run
  against both, is needed before the contract is deployed.

## Update, 0.2

The shared scenarios now exist: `packages/escrow-core/vectors/settlement.json` is generated by
the engine's tests and reproduced by the contract's. See
[ADR 0006](0006-every-waiting-state-has-a-deadline.md) for the deadlines added in the same
release.
